# D4 性能 · 并发吞吐与尾部延迟（p99）实测

> 日期：2026-08-06 · Apple Silicon · `examples/d4_concurrent.rs`

## 结论

**Send+Sync 的共享链在并发读下无锁无争用：吞吐近线性扩展（4 线程 3.3×），p99 尾部延迟恒定 42ns 不随并发恶化。** RCU 快照读路径的"不影响全局"承诺在并发维度成立。

## 实测（3 中间件链：Add/Cap/Add + 核心，Arc 共享）

| 场景 | 每 op | 吞吐 | p50 | **p99** |
|---|---|---|---|---|
| 1 线程 × 1M | 6.8 ns | 146.6 M ops/s | ~0 ns | **42 ns** |
| 4 线程 × 250k | 2.1 ns（聚合） | 485.7 M ops/s（3.3×） | ~0 ns | **42 ns** |
| 8 线程 × 125k | 1.7 ns（聚合） | 586.5 M ops/s | ~0 ns | **42 ns** |

## 关键发现

- **p99 恒定 42ns**：并发线程数不恶化尾部延迟——无锁读（RCU）无争用放大，验证 D4"不影响全局"。
- **近线性扩展**：1→4 线程 3.3×（理想 4×，少量调度/缓存开销）；4→8 撞核数与内存带宽（1.2×）。
- p50≈0ns：单次采样 op 太快，Instant 分辨率下归零；p99=42ns 是真实尾部（调度/缓存 miss）。

## 判定

| D4 承诺 | 判定 |
|---|---|
| 读路径无锁、不影响全局 | ✓ 并发不恶化 p99 |
| Send+Sync 生产可用 | ✓ 近线性扩展 + 恒定尾部 |
| 并发维度（此前盲点） | ✓ 已补齐 |

## 复现

cargo run --example d4_concurrent --release
