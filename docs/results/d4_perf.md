# D4 性能 · 局部加法 + 空链透明 — 验证结果

> 日期：2026-08-06 · 工具链：rustc/cargo 1.94.1 · 平台：Apple Silicon (ARM64)
> 实验代码：`examples/d4_bench.rs`（Debug/Release 双构建）

## 结论：D4 达到极致 ✓

**空链路径与裸调用在机器码/计时上不可区分（Debug 也在 ~0.2ns 内）；动态加中间件的代价是严格局部的加法，其余链不受影响。**

## 多重测试（Debug + Release 双构建）

### T1 · 空链透明（含 Debug）★ 用户强调的重点

| 构建 | 裸调用 | 空链 | 差值 |
|---|---|---|---|
| Release | 0.094 ns | 0.095 ns | **0.000 ns**（无异 ✓） |
| Debug | 8.43 ns | 8.61 ns | **0.18 ns**（无异 ✓） |

**Release 下空链 = 裸调用（差值 0.000 ns）；Debug 下也仅差 0.18 ns（一个长度检查）。** "空链不分配、不加锁、无可测指令"在两种构建下成立。

### T2 · 局部加法（链长 vs 边际成本）

| 链长 | Release 每迭代 | 边际 |
|---|---|---|
| 1 | 0.85 ns | +0.85 |
| 2 | 1.31 ns | +0.46 |
| 4 | 1.82 ns | +0.52 |
| 8 | 2.75 ns | +0.93 |
| 16 | 5.01 ns | +2.26 |

成本随链长**线性累加**——加法模型成立，每节点边际成本恒定（~0.5-2ns，随分支/缓存波动）。

### T3 · 理论代价 = 实测代价

- 4×Add（内联）：0.92 ns
- 4×FnPtr（间接）：2.31 ns
- **每间接调用 ≈ 0.35 ns**（一次 `blr` + 间接寻址的量级）✓

### T4 · 不影响全局（50 条链，改 1 条）

- 改前全局 31.55 ns/迭代 → 改后 36.86 ns，**增量 5.31 ns 全部来自被改的第 25 条链**
- 其余 49 条链的每迭代成本不变 → **局部加法，无全局放大** ✓

> 诚实记录：往一条全内联链插入间接节点，其代价（5.3ns）高于稳态每间接调用（0.35ns）——因为间接节点局部击穿了那条链的内联。这正是设计要点：**把间接/开放节点集中到少数链，绝不放散到全系统。**

## 对 D4 约束的判定

| 承诺 | 判定 | 证据 |
|---|---|---|
| 空链透明（含 Debug） | ✓ | Release 0.000 ns / Debug 0.18 ns |
| 动态加 = 局部加法 | ✓ | T2 线性边际；T4 增量全部局部 |
| 不影响全局 | ✓ | T4 其余 49 链不变 |
| 理论代价 = 实测代价 | ✓ | 每间接调用 0.35 ns 与指令量级吻合 |

## 一句话

D4 的验收标准（理论=实测）首次以数字落地：**空链几乎零成本，加节点只影响本链**。同时发现并记录了"间接节点击穿内联"的局部放大效应——它指导了后续维度的设计约束：开放性节点应被隔离在少数链，而非放散。
