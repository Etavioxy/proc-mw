# D7/L3 · 永不卸载的内存代价量化

> 日期：2026-08-06 · Apple Silicon · `examples/d7_plugin_memory.rs`

## 结论

**L3"永不 unload"的内存代价比担心的低：同一插件经 mmap 共享代码页，加载 200 次仅 +160KB（~1KB/句柄），增长有界而非线性。**

## 实测（加载同一 d6_plugin 200 次）

| 加载数 | RSS | 增长 | 每插件 |
|---|---|---|---|
| 40 | 1616 KB | +128 KB | +3 KB |
| 80 | 1648 KB | +160 KB | +2 KB |
| 120 | 1648 KB | +160 KB | +1 KB |
| 200 | 1648 KB | +160 KB | +1 KB |

**增长在 ~80 次后趋于平台**——同一 .so 的代码页被 mmap 共享，每次新增的只是句柄/数据页。

## 判定

- **L3 代价有界**（同插件场景）：~1KB/句柄，平台后不增长。
- **不同版本热替换**（每次新 .so）：新代码页不共享，增长 ≈ 每版本 .so 的代码大小——这是"永不卸载 + 热替换"的真实成本，但每次替换是有界的、可预期的。
- 设计含义：若热替换频繁且版本众多，内存 = Σ 各版本 .so 大小；可在"卸载（L3 风险）"与"内存增长"间权衡，或限制保留版本数。

## 复现

```bash
cargo build -p d6_plugin --release
cargo run --features runtime --release --example d7_plugin_memory
```
