# 场景 S06 · 独立草稿 —— 追踪传播

## 用户故事
> 作为**可观测**，我想**每请求携带 trace_id 贯穿 Service 调用链**，以便**端到端定位延迟**。

## 设计决策
1. **trace 在共享类型**：`ServiceReq.trace_id`（0 = 未注入）——上下文在请求字段（非 Ctx）。
2. **注入是运行期编译插件**（可热更）：v1 派生 `id^0xDEAD` → v2 `id^0xBEEF`。
3. **幂等**：已注入（trace_id != 0）不覆盖——传播语义正确。
4. **直接共享类型**（usergoals）。

## 待测试点
- [x] 未注入请求经插件注入（v1 派生）。
- [x] trace 逻辑热更（v1→v2 派生变化）。
- [x] 已注入 trace 幂等保持。
- [ ] 跨多个 Service 传递（trace 贯穿链）。

## 边界反思
- trace 派生是纯函数（可从 id 重算）——热更只是换派生规则。
- 若 trace 需从外部注入（不依赖请求内容），走宿主 Stateful 节点（无状态插件做不到
  "读取外部上下文"）。
