# 场景 S07 · 独立草稿 —— 异步桥（tower `buffer` 语义）

## 用户故事
> 作为**架构**，我想**同步调用经缓冲桥接到异步后端**，以便**调用方不被慢后端阻塞**。

## 设计决策
1. **有界缓冲（flume bounded）+ 消费者线程**：`call` 经链（metrics + 变换插件）后入缓冲
   立即返回"accepted"；消费者异步处理后端。
2. **背压**：缓冲满 → `Err(BufferFull)`（返回码 2 语义，调用方感知）。
3. **直接共享类型**（usergoals）：`shared_types::ServiceReq`。
4. **async 块不捕获 &mut self**：克隆 `Sender` 再进块（future 需 Send）。

## 待测试点
- [x] 缓冲 2：3 请求 → 2 accepted + 1 BufferFull。
- [x] 调用方立即返回（29.9µs 非阻塞）。
- [x] 消费者异步处理全部（含变换标记）。
- [x] 缓冲释放后恢复接收。
- [ ] 消费者故障时缓冲堆积/丢弃策略。

## 边界反思
- 桥的"返回即接收"与"真正完成"分离——幂等/至少一次语义需在上层保证。
- 消费者线程是宿主结构；桥两端的中间件可独立热更。
