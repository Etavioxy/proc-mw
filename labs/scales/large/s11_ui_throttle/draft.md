# 场景 S11 · 独立草稿 —— UI 事件节流

## 用户故事
> 作为**玩家**，我想**高频 UI 事件（连点/滚轮）被节流**，以便**UI 不卡顿、不误触发**。

## 设计决策
1. **节流状态在插件内**（静态 last-click 时间戳，任意 Rust）；v1(100ms) → v2(200ms) 热更。
2. **直接依赖宿主**（usergoals）：`large_service::UiEvent`。
3. **高频 = 返回码 2**（不达 bevy）。

## 待测试点
- [x] v1 节流第 2 次高频点击（2/3 通过）。
- [x] 热换 v2 更严（1/3 通过）。
- [x] 节流状态跨点击保持（插件内静态）。
- [ ] 节流窗口基于系统时钟（真实验证需 sleep）。

## 边界反思
- 插件内静态状态跨热更归零（有状态插件热更边界）；若节流需跨热更保留，状态落宿主。
- 系统时钟测试依赖 sleep——演示用真实时间节流。
