# 场景 S12 · 独立草稿 —— 世界状态逻辑热更（旗舰）

## 用户故事
> 作为**运营**，我想**游戏运行中热更世界状态逻辑（经济数值/掉落表）**，以便**线上活动即时
> 调整、不停服**。

## 设计决策
1. **世界逻辑 = 可热更插件**：v1（掉落 1%）→ v2（掉落 3%），`chain.set` 热替换。
2. **世界更新不停**：bevy Schedule 持续跑，热替换只换链节点（RCU 快照）。
3. **直接依赖宿主**（usergoals）：`large_service::WorldState`。

## 待测试点
- [x] v1 掉落率 1%（3 帧）。
- [x] 热换 v2 掉落率 3%（3 帧，世界不停）。
- [x] bevy Schedule 持续更新。
- [ ] 热更影响面量化（玩家可感知的经济变化）。

## 边界反思
- 掉落表等世界逻辑天然可热更（无状态纯函数插件）——proc-mw 核心目的的典型落地。
- bevy 生态无运行期热更插件机制；proc-mw 补齐（插件依赖宿主 crate 直接共享类型）。
