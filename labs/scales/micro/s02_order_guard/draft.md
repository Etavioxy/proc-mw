# 场景 S02 · 独立草稿 —— 订单创建防护

## 用户故事
> 作为**商家**，我想**无效订单（负数金额）被快速拒绝、且在错误尖峰时自动熔断后续下单**，
> 以便**下游结算系统不被错误流量打垮**。

## 设计决策
1. **直接共享类型**（usergoals）：请求 = `shared_types::MicroReq`（非 repr(C)）。
2. **守卫插件**（运行期编译）：`value < 0` → 返回码 2（拒绝）；标记 audited 放行。
3. **熔断包装**：`CircuitBreaker::call_opaque`——负单 3 连 → 打开 → 合法订单快速失败；
   冷却后半开放行 → 恢复。
4. **错误域收口**：拒绝 = 返回码，不 panic。

## 待测试点

- [x] 负单尖峰 3 次 → 熔断打开 → 正单也快速失败。

## 边界反思
- 守卫是可热更插件（规则可换），熔断在宿主包装层（状态跨热更保留）。
- 快速失败路径零计量——保护观测语义。
